01 — Project Overview

What is CampaignOS?

CampaignOS is an AI-powered marketing campaign generation platform. A marketer fills in a brief — brand, product, budget, target audience, and a "Fan Truth" — and a pipeline of AI agents autonomously produces a complete campaign: brand strategy, ad copy, key visual, channel adaptations, landing page, email, Instagram image post, and Instagram Reel — all in a single pipeline run.

The system is built around Google's Agent Development Kit (ADK), orchestrating 10+ specialist agents as a Directed Acyclic Graph (DAG). Each agent has a single responsibility, a typed input/output schema, and passes structured JSON to the next agent in the chain.
One-line answer for "what did you build?": A multi-agent AI system that takes a marketing brief and autonomously produces a full campaign — strategy, copy, visuals, and publishes to Google Ads, email, and Instagram — using Google ADK, Gemini, Veo, and FastAPI on Cloud Run.

03 — Pipeline Workflow

How the Pipeline Works — Step by Step

1
FUNCTION NODE

load_brand_context

Reads brand guidelines from GCS. Queries Vertex AI Search for Fan Truth examples, KPI benchmarks, channel benchmarks, and customer segments from BigQuery. Injects all data into agent context — no LLM calls yet.

2
LOGOS — briefing_agent

Brief Validation + Fan Truth Scoring

Validates the brief. Scores Fan Truth on 3 dimensions (Specific / Shared / Special, each 0–100). Flags KPIs as OK / AMBITIOUS / UNREALISTIC against historical benchmarks. Produces a MachineBrief JSON with all enriched data.

3
AETHER — culture_analyst

Live Cultural Research

Uses Google Search tool to find relevant cultural trends, audience behaviours, and seasonal moments. Multi-turn agent — can call google_search multiple times before finishing.

4
AETHER — culture_formatter

Structure Cultural Intelligence

Turns raw search results into a typed CultureAnalysis JSON: key cultural summary, sentiment metrics, and 3–5 concrete cultural hooks for the campaign.

5
HELIA — creative_director

Big Idea + Creative Strategy

Synthesises brief + cultural intelligence → Big Idea title, visual world, hero message, tone, channel priorities, messaging pillars, and a handoff brief to the art directors.

6
copy_agent

Campaign Copy — Three Length Variants

Writes short (≤6 words for KV/OOH), medium (social/display), and long (press/editorial) copy. Also generates channel-specific lines: Instagram caption, email subject, web headline, TikTok hook.

7a
IDEON — kv_generator_1

Key Visual Art Direction — Concept A (PARALLEL)

Writes art direction for Key Visual concept A: composition, colour palette, typography guidance, image prompt for Gemini.

7b
IDEON — kv_generator_2

Key Visual Art Direction — Concept B (PARALLEL)

Different compositional lens to the same brief. Running in parallel gives the ranker two genuine creative alternatives.

8a
MORPHIS — kv_image_agent_1

Image Generation — Concept A (PARALLEL)

Calls generate_and_save_kv_image tool → Gemini 3 Pro Image model. Saves result to GCS and ADK artifact store.

8b
MORPHIS — kv_image_agent_2

Image Generation — Concept B (PARALLEL)

Same as 8a but for Concept B. A JoinNode waits for both 8a and 8b to complete before the pipeline continues.

9
KINETIK — kv_ranker

Rank + Select Best Key Visual

Evaluates both KV concepts against brand compliance, Fan Truth alignment, and creative strength. Selects the winner with a written rationale.

10

Human-in-the-Loop KV Selection

Pipeline pauses here. The UI shows both KV concepts side by side. The human approves the AI selection or overrides it. Pipeline resumes with the chosen concept.

11

Channel Adaptation

Routes content tasks per channel (Instagram, TikTok, Website, Email). Adapts the hero creative for each format's specs — aspect ratios, copy lengths, visual hierarchy.

12

Pre-Launch Performance Forecast

Generates predicted reach, CTR, ROAS per channel based on historical benchmarks. Flags top risk, top opportunity, and first-48h watchlist metrics.

★
KINETIK — Creative Pipeline (async)

Veo Reel Generation + Channel Assets

Runs in parallel with the ADK DAG. Generates a 6-second Veo video saved to GCS, plus website banner and email header adaptations of the key visual.

04 — Key Concepts

Technical Concepts You Must Know

Fan Truth

Not a product claim — a real human insight the audience already believes. Scored on three axes: Specific (not generic platitude), Shared (widely held in the audience), Special (culturally resonant). All three must exceed 70 for PASS. Fail triggers a suggested alternative from the briefing agent.

Brand Locks

Non-negotiable brand rules enforced as Pydantic fields: token placement, voice archetype, headline word limit (6), caption char limit (200), CTA word limit (3), colour ratios per dwell time. The AI cannot override these — they are constraints injected into every agent's system prompt.

ADK Workflow DAG

Google's Agent Development Kit lets you define a directed acyclic graph of agents. Edges define execution order. Fan-out = two edges from one node (parallel). Fan-in = JoinNode that waits for all upstream agents before continuing. No custom orchestration code needed.

Server-Sent Events (SSE)

Frontend opens GET /events/{campaign_id} — a persistent HTTP connection. The server pushes JSON events as each agent completes: {"agent":"Logos","status":"done","message":"Brief validated ✓"}. Uses asyncio.Event to wake the SSE generator. No polling, no WebSockets.

Instagram API — Two Flows

Image post: POST /media (create container with image_url) → POST /media_publish.
Reel: POST /media with media_type=REELS + video_url → poll GET /{id}?fields=status_code until FINISHED → POST /media_publish. Polling required because video processing takes time.

GCS Uniform Bucket Access

Bucket uses IAM-only access (no legacy ACLs). blob.make_public() fails with 400 Cannot get legacy ACL. Fixed by IAM binding: allUsers → roles/storage.objectViewer. All objects become publicly readable via https://storage.googleapis.com/{bucket}/{path} without per-object ACLs.

RAG Architecture

Retrieval-Augmented Generation: brand guidelines (GCS) + historical data (BigQuery) are indexed in Vertex AI Search. load_brand_context queries the search engine and injects the top results into the agent's context window before any LLM call — giving agents grounded knowledge without hallucination.

pgvector / Semantic Search

Customer segment data (Kaggle CDP) is embedded using Gemini Embedding 2 (768 dims) and stored in PostgreSQL with the pgvector extension. Semantic search finds the most relevant customer segments for an audience description. Same schema runs in Docker locally and Cloud SQL in production.

06 — Interview Q&A

Common Questions — Model Answers

Why use an agent framework (ADK) instead of just calling APIs directly?
ADK handles agent state, message routing between agents, tool call execution, retries, and the fan-out/fan-in pattern automatically. Without it, you'd write hundreds of lines of boilerplate to manage context passing between 15 agents, track which agents completed, merge parallel results, and handle HITL gates. The Workflow DAG also makes the architecture self-documenting — you can see the entire pipeline in 20 lines of edge definitions.
How do you handle the 3–5 minute Veo reel generation without timing out?
The creative pipeline is fully async — generate_campaign_reel() uses asyncio.sleep between Veo operation polls, so the event loop stays free for other requests. Cloud Run timeout is set to 3600s (1 hour). The frontend never waits for the reel directly — it receives a video_b64 milestone event via SSE when the reel is ready, which can arrive at any point during the pipeline run. The publish step separately checks GCS for the reel file.
Why run two KV generators in parallel?
Each generator brings a different compositional lens to the same brief. Running them in parallel (fan-out) costs the same wall-clock time as one but gives the KV Ranker two genuine creative alternatives to evaluate. This improves output quality without increasing total pipeline time. The JoinNode (fan-in) ensures both image agents complete before ranking begins.
How do you enforce brand compliance across all AI-generated content?
Three layers: (1) Brand Locks — a Pydantic model with non-negotiable constraints (headline ≤6 words, CTA ≤3 words, token placement, colour ratios) injected into every agent's system prompt. (2) Brand warnings — the briefing agent flags rule violations in the brief before strategy begins. (3) KV Ranker explicitly uses brand compliance as a selection criterion when choosing between the two key visual concepts.
How does data retrieval work? (RAG)
Retrieval-Augmented Generation. Brand guidelines (Markdown files in GCS) and structured data (historical campaigns, Fan Truth library, channel benchmarks in BigQuery) are indexed in Vertex AI Search. The load_brand_context function node runs before any LLM call — it queries the search engine and injects the top-ranked results into the agent's context. The LLM never needs to call a tool to get this data; it arrives pre-loaded, which eliminates tool-call latency and hallucination risk.
Why Cloud Run instead of GKE or Cloud Functions?
Cloud Run hits the sweet spot: serverless (no cluster to manage), supports a 1-hour request timeout which is required for Veo generation — Cloud Functions caps at 9 minutes which is too short. Cloud Run also has built-in Cloud SQL proxy, Secret Manager integration, and scales to zero between demo runs. GKE would be overkill for the current scale. The pipeline takes 4–8 minutes per campaign, so Functions are ruled out by the timeout alone.
How does Instagram publishing work technically?
Two separate flows via the Meta Graph API. Image post: POST to /{ig-user-id}/media with the image URL (must be publicly accessible HTTPS — served from GCS) → POST to /{ig-user-id}/media_publish with the creation ID. Reel: POST to /media with media_type=REELS and video_url → poll GET /{creation-id}?fields=status_code every 5 seconds until status_code=FINISHED (or timeout at 5 minutes) → POST /media_publish. Token is a 60-day long-lived User Token exchanged from a short-lived Explorer token via fb_exchange_token.
What is a Fan Truth and why does it matter for campaign quality?
A Fan Truth is the real human insight at the heart of the campaign — not a product claim ("our shampoo is gentle") but something the audience already believes ("the first moment of a truly clean scalp is the only reset I trust"). It's scored on Specific (is it precise, not a generic cliché?), Shared (does the wider audience hold this belief?), and Special (does it tap into a culturally resonant moment?). All three must score above 70. A failing Fan Truth is flagged before strategy begins — preventing the entire downstream pipeline from building on a weak insight.
How do secrets get managed across dev and production?
In development: all secrets live in harness/.env which is gitignored — never committed. In production on Cloud Run: sensitive values (Instagram access token, Google API key, email password, Groq key) are stored in Google Cloud Secret Manager and injected at container startup via --set-secrets in the Cloud Run deploy command. Non-sensitive config (account IDs, bucket names, model names) are passed as plain --set-env-vars. The cloudbuild.yaml wires all of this together in the deploy step.
How does real-time streaming work in the UI?
The frontend opens a persistent HTTP connection to GET /events/{campaign_id}. FastAPI responds with text/event-stream (Server-Sent Events). Each agent's completion triggers push_event() which appends a JSON object to an in-memory list and calls asyncio.Event.set(). The SSE generator is awaiting that event — when woken, it reads all new events from its last read position and streams them to the browser. The browser renders each event as an agent card update in real time. No polling, no WebSocket handshake, no reconnect overhead.
