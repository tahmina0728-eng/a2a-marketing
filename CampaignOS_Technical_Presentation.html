What Is CampaignOS?
Overview
Say this: CampaignOS is an end-to-end AI-powered campaign production platform. A marketing team fills in one brief — brand, product, audience, budget, channels — and the system produces a validated strategy, campaign copy, hero visual, a six-second video reel, and a pre-launch performance forecast. Everything a team would normally spend two weeks producing, delivered in under five minutes.
Three Pillars
Multi-Agent AI Pipeline
Powered by Google ADK 2.0. Specialised agents each own one stage of the creative process and hand off structured data to the next agent via a Directed Acyclic Graph.
Real-Time Frontend
React + TypeScript UI that streams live agent progress over Server-Sent Events — every agent's status visible in real time.
Google Cloud Infrastructure
Vertex AI (Gemini, Imagen 4, Veo), Vertex AI Search, Cloud SQL + pgvector, BigQuery, Cloud Storage, Cloud Run.

Backend: FastAPI Application & Routes
Backend
Say this: The backend is a FastAPI application running as an async Python server. The key design decision: when a campaign starts, the HTTP response closes immediately and the pipeline runs as a background asyncio task. The frontend tracks progress via the SSE stream, never blocking on a long HTTP call.
RouteMethodPurpose
/campaignPOSTStart campaign → returns campaign_id in milliseconds, pipeline runs in background
/events/{id}GETSSE stream — holds connection open, pushes events as agents complete
/briefPOSTRun briefing stage only via ADK (synchronous)
/brief-fullPOSTBrief + Strategy + Copy synchronously — no streaming
/pipelinePOSTFull ADK DAG — all agents, no SSE streaming
/healthGETCloud Run liveness probe
/readinessGETChecks agents + search client are loaded
/landing/{id}GETServes the AI-generated brand landing page HTML
SSE Architecture — Zero CPU Blocking
# Per-campaign event store in memory
_pipelines: dict[str, dict] = {
  "campaign-abc-123": {
    "events": [...],             # list of all events so far
    "signal": asyncio.Event()    # wakes SSE generator when new event arrives
  }
}

# SSE generator — runs per connected client
async def generate():
    idx = 0
    while campaign_id in _pipelines:
        while idx < len(events):
            yield f"data: {json.dumps(events[idx])}\n\n"
            idx += 1
        await asyncio.wait_for(signal.wait(), timeout=600)
        # ↑ Suspends here — zero CPU — until push_event() wakes it

Two Execution Paths
Architecture
Path A — /campaign (UI path)
Hand-coded async orchestrator in main.py. Calls runner.py functions directly in sequence. Emits SSE events at every stage. This is what the frontend uses. Maximum control over timing, logging, and event shaping.
Path B — /pipeline (ADK DAG)
Pure Google ADK Workflow. Uses root_agent from pipeline.py — full DAG with fan-out, fan-in (JoinNode), and HITL gates. Accessed via adk web or /pipeline endpoint. The architecturally "correct" ADK path.

Design Principles & Architecture Decisions
Architecture
No Model Hallucination on Brand Data

Brand guidelines, logos, and colour codes are loaded from GCS at the start of every pipeline run — they are never in the model's training data. load_brand_context retrieves the current, authoritative guidelines and injects them directly into the context window. Brand locks (font, colours, forbidden words) are passed as a typed BrandLocks model through every stage.

Structured Outputs via Pydantic

Every agent produces a typed Pydantic model as output. If the LLM returns malformed JSON, _parse_agent_response() strips markdown fences and retries. Downstream agents always receive clean, validated data — never raw text to interpret.

Fan Truth as a Quality Gate

The Fan Truth score governs three things: (1) whether the brief passes to creative stage, (2) the performance forecast confidence level, and (3) the BigQuery audit record for trend analysis. It is not decorative — it is a data signal that flows through the entire pipeline.

SSE vs WebSocket

Server-Sent Events are used rather than WebSockets. SSE is unidirectional (server → client only), simpler to scale on Cloud Run, and natively supported by the browser's EventSource API with built-in reconnection. No WebSocket upgrade handshake overhead.

Fire-and-Forget BigQuery Logging

The BigQuery write runs as asyncio.create_task() immediately after the briefing stage. It never blocks the pipeline. If it fails, a warning is logged but the campaign continues unaffected.

KV Fan-Out / Fan-In Pattern

Two art directors run in parallel (Python asyncio + ADK JoinNode). This halves the KV generation time and produces creative diversity — graphic-led vs image-led. The ranker evaluates both and selects the stronger concept before proceeding. In the ADK DAG path, the JoinNode enforces both must complete before continuing.
